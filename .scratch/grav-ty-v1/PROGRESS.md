- Files touched: src/sim/gravity.lua, src/sim/field.lua, src/game/config.lua (gravity.G/softening, field.cellSize, boundary.margin), src/game/match.lua, src/app/input.lua, src/app/render/debug_overlay.lua, src/app/states/match_state.lua, tests/unit/{gravity,field}_test.lua (new, registered in tests/unit/run.lua), tests/unit/match_test.lua, tests/e2e/field_overlay_test.lua, tests/support/game_harness.lua (outside slice's list — added the same ctx.debug/Input.update/DebugOverlay.draw wiring, guarded with `if love then` since the integration tier drives this harness with no `love` global)
- New exports/interfaces: `Field.bake(level, config) -> field` where `field = {cellSize, cols, rows, minX, minY, cells = {{x, y, mass, ax, ay}, ...}}` (row-major, 1-based). `Field.sample(field, x, y) -> {x = ax, y = ay}`. `Gravity.pointMass(dx, dy, m, G, eps) -> ax, ay` (returns two numbers, not a table). `Input.newDebugState() -> {showField, showGrid, ...}`, `Input.update(state)` (rising-edge F1/F2 polling). `DebugOverlay.draw(ctx)` plus `.drawFieldArrows/.drawGrid/.drawWorldOutlines`. `ctx.debug` is a new app-layer-only ctx field (src/game/match.lua never touches it).
- Conventions confirmed: new unit test files registered in tests/unit/run.lua defaultTestFiles. e2e tests use GameHarness.startMatch(level, {real=true}) + FakeInput + FrameStepper + Capture.capture.
- Surprises: cell-centre-inclusion rasterisation quantization made the "two equal worlds → near-zero midpoint" test show real asymmetry unless worlds are grid-aligned (position/size multiples of cellSize) — fixed by aligning the test fixtures, not the physics. The "no discontinuity across a cell edge" check needed a scale-relative tolerance (tiny-step vs whole-cell change) since the field has genuine nonzero slope near a world. Chosen tuning values (gravity.G=2000, softening=20, field.cellSize=16, boundary.margin=128) are placeholders, not derived from a design doc — a later slice may want to retune for gameplay feel.
